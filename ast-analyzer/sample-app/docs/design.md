# sample-app 外部仕様書

## 概要

sample-app は Spring MVC + MyBatis + H2 で構築された EC サイトのサンプルアプリケーション。
ユーザー管理・商品管理・注文管理の 3 機能から成る。

| 技術 | 内容 |
|------|------|
| バックエンド | Java 11, Spring MVC 5.3, MyBatis 3.5 |
| フロントエンド | JSP + JSTL, バニラ JavaScript (AJAX) |
| データベース | H2（インメモリ） |
| 認証 | セッションベース |

---

## 画面一覧

| 画面名 | URL | 認証要否 |
|--------|-----|----------|
| ログイン | `/user/login` | 不要 |
| 新規ユーザー登録 | `/user/register` | 不要 |
| マイページ | `/user/mypage` | 必要 |
| 商品一覧 | `/product/list` | 不要 |
| 商品詳細 | `/product/detail/{id}` | 不要 |
| 商品編集・新規登録 | `/product/edit/{id}` / `/product/new` | 不要 |
| 注文履歴 | `/order/list` | 必要 |
| 注文詳細 | `/order/detail/{id}` | 必要 |

## 画面仕様

### 1. ログイン画面 (`/user/login`)

**機能概要**
ユーザー名とパスワードを入力してログインする。

**表示内容**
- ユーザー名入力フィールド
- パスワード入力フィールド
- ログインボタン
- 新規登録リンク

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| ログインボタン押下 | ユーザー名でユーザーを検索し、一致すればセッションに保存 | 商品一覧画面 |
| ログイン失敗 | エラーメッセージを表示 | ログイン画面（再表示） |
| 新規登録リンク押下 | — | 新規ユーザー登録画面 |

---

### 2. 新規ユーザー登録画面 (`/user/register`)

**機能概要**
新規ユーザーを登録する。

**表示内容**
- ユーザー名入力フィールド（必須）
- メールアドレス入力フィールド（必須）
- 登録ボタン

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| 登録ボタン押下 | ユーザー情報を DB に登録 | ログイン画面 |
| 入力不足 | バリデーションエラー表示 | 登録画面（再表示） |

---

### 3. マイページ (`/user/mypage`)

**機能概要**
ログイン中のユーザー情報を確認・更新する。

**表示内容**
- ユーザー名（表示のみ）
- メールアドレス（編集可能）
- 更新ボタン
- ナビゲーション（商品一覧 / 注文履歴 / ログアウト）

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| 画面表示 | セッションからユーザー情報を取得して表示 | — |
| 更新ボタン押下 | メールアドレスを DB に保存 | マイページ（再表示） |
| ログアウトリンク押下 | セッションを無効化 | ログイン画面 |

---

### 4. 商品一覧画面 (`/product/list`)

**機能概要**
登録済み商品の一覧を表示する。カテゴリでの絞り込みと、カートへの追加・注文が行える。

**表示内容**
- ナビゲーション（マイページ / 注文履歴 / ログアウト）
- 検索エリア
  - カテゴリ選択ドロップダウン（すべてのカテゴリ / 電子機器 / 衣類 / 食品）
  - 検索ボタン（フォームサブミット）
- 商品テーブル（ID / 商品名リンク / カテゴリ / 価格 / 在庫 / 操作列）
  - 操作列（サーバーレンダリング時）: 編集ボタン / 削除ボタン / カートに追加ボタン
  - 操作列（AJAX 再描画時）: カートに追加ボタンのみ
- アクションエリア
  - 新規商品登録ボタン
  - 注文するボタン
- カートパネル（商品追加時のみ表示、初期は非表示）
  - 追加済み商品の一覧（商品名 × 数量 = 小計）
  - 合計金額
  - チェックアウトボタン

**カテゴリ絞り込みの二重動作**

カテゴリ絞り込みには 2 つの経路がある：

| 操作 | 方式 | 備考 |
|------|------|------|
| ドロップダウン変更（change イベント） | AJAX で `/product/api/list?category=` を取得しテーブルを非同期再描画 | ページリロードなし。操作列は「カートに追加」のみ |
| 検索ボタン押下 | フォームを GET サブミット → `/product/list?category=` へ遷移 | ページリロードあり。操作列に編集・削除ボタンも表示 |

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| カテゴリドロップダウン変更 | AJAX で `/product/api/list` を取得し、テーブルを非同期再描画 | 同画面（テーブル更新、ページリロードなし） |
| 検索ボタン押下 | フォーム GET サブミット → サーバーサイドでカテゴリフィルタリング | 同画面（ページリロードあり） |
| 商品名リンク押下 | — | 商品詳細画面 |
| 編集ボタン押下（サーバーレンダリング時のみ） | — | 商品編集画面 |
| 削除ボタン押下（サーバーレンダリング時のみ） | 確認ダイアログ → POST `/product/delete/{id}` で商品を削除 | 商品一覧（再表示） |
| カートに追加ボタン押下 | AJAX で `/product/api/detail/{id}` を取得し、カートに 1 個追加（同商品が既存なら数量 +1）。カートパネルを表示 | 同画面（カートパネル更新） |
| 注文するボタン押下 | カート内容で `/order/place` に POST。成功後 1.5 秒待機して遷移 | 注文詳細画面 |
| チェックアウトボタン押下 | 注文するボタンと同じ処理（`placeOrder()` を呼び出す） | 注文詳細画面 |
| 新規商品登録ボタン押下 | — | 商品編集画面（新規作成） |

**カート管理**
- カートはクライアント側（JavaScript 変数 `cart`）で管理。ページリロードでリセットされる
- カートが空の場合、カートパネルは非表示
- 注文成功後、カートは空になりカートパネルが非表示になる
- カートが空の状態で注文するボタンを押すとエラーメッセージを表示

**エラーハンドリング**
- 在庫不足などのエラーはサーバーから JSON で返され、画面上にメッセージ表示
- 401 エラー（未ログイン）で注文した場合はログイン画面へリダイレクト

### 5. 商品詳細画面 (`/product/detail/{id}`)

**機能概要**
選択した商品の詳細情報を表示し、購入操作を行う。

**表示内容**
- 商品名・カテゴリ・説明・価格・在庫数
- 数量入力フィールド
- カートに追加ボタン
- 今すぐ購入ボタン
- 編集リンク・削除リンク

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| カートに追加ボタン押下 | 指定数量を商品一覧画面のカートに追加 | 商品一覧画面 |
| 今すぐ購入ボタン押下 | 指定数量で即座に注文を作成（在庫チェックあり） | 注文履歴画面 |
| 編集リンク押下 | — | 商品編集画面 |
| 削除リンク押下 | 確認ダイアログ → 商品を DB から削除 | 商品一覧画面 |

---

### 6. 商品編集・新規登録画面 (`/product/edit/{id}` / `/product/new`)

**機能概要**
商品情報を新規登録または編集する。

**表示内容**
- 商品名入力フィールド（必須）
- 説明入力フィールド
- 価格入力フィールド（必須）
- 在庫数入力フィールド（必須）
- カテゴリ選択ドロップダウン（電子機器 / 衣類 / 食品）
- 保存ボタン・キャンセルボタン

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| 保存ボタン押下（新規） | 入力値を検証し、商品を DB に登録 | 商品一覧画面 |
| 保存ボタン押下（編集） | 入力値を検証し、商品情報を DB に更新 | 商品詳細画面 |
| キャンセルボタン押下 | — | 商品一覧画面 |
| バリデーションエラー | エラーメッセージを表示 | 編集画面（再表示） |

---

### 7. 注文履歴画面 (`/order/list`)

**機能概要**
ログイン中のユーザーの注文一覧を表示する。

**表示内容**
- 注文テーブル（注文ID / 注文日 / 合計金額 / ステータス / 操作列）
  - ステータスが `PENDING` の場合のみ「キャンセル」ボタンを表示
- 注文がない場合はメッセージと商品一覧へのリンク

**ステータス値**

| 値 | 意味 |
|----|------|
| `PENDING` | 注文済み・未完了 |
| `COMPLETED` | 受け取り完了 |
| `CANCELLED` | キャンセル済み |

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| 注文ID リンク押下 | — | 注文詳細画面 |
| キャンセルボタン押下 | 確認ダイアログ → ステータスを `CANCELLED` に変更 | 注文履歴（再表示） |

---

### 8. 注文詳細画面 (`/order/detail/{id}`)

**機能概要**
選択した注文の詳細を表示し、受け取り完了操作を行う。

**表示内容**
- 注文ID・注文日・ステータス・合計金額
- 注文商品テーブル（商品ID / 数量 / 単価 / 小計）
- ステータスが `PENDING` の場合のみ「受け取り完了」ボタンを表示

**処理フロー**

| 操作 | 処理 | 遷移先 |
|------|------|--------|
| 受け取り完了ボタン押下 | 確認ダイアログ → ステータスを `COMPLETED` に変更 | 注文詳細（再表示） |
| 注文履歴リンク押下 | — | 注文履歴画面 |

## 画面遷移フロー

```
ログイン画面 ←───────────────────────── ログアウト
    │
    ↓ ログイン成功
商品一覧画面 ──────────────→ 商品詳細画面 ──→ 商品編集画面
    │  ↑                         │
    │  │ カートに追加              │ 今すぐ購入
    │  └─────────────────────────┘
    │
    │ 注文する（カート）
    ↓
注文履歴画面 ──────────────→ 注文詳細画面
    ↑
マイページ
```

## API エンドポイント一覧

画面からの非同期通信で使用される JSON API。

| エンドポイント | メソッド | 説明 |
|----------------|----------|------|
| `/product/api/list?category=` | GET | カテゴリ別商品一覧（JSON） |
| `/product/api/detail/{id}` | GET | 商品詳細（JSON） |
| `/order/place` | POST | 注文作成（JSON リクエスト/レスポンス） |
| `/order/cancel/{id}` | POST | 注文キャンセル |
| `/order/api/complete/{id}` | POST | 注文完了マーク |

**注文作成リクエスト例**
```json
{
  "items": [
    { "productId": 1, "quantity": 2, "unitPrice": 1000 }
  ],
  "totalAmount": 2000
}
```

**注文作成レスポンス例**
```json
{ "success": true, "orderId": 42 }
// または
{ "error": "在庫が不足しています" }
```

## データモデル概要

```
users
  id, username, email, role

products
  id, name, description, price, stock, category

orders
  id, user_id, order_date, status, total_amount

order_items
  id, order_id, product_id, quantity, unit_price
```

**注:** H2 インメモリ DB のためアプリ再起動でデータはリセットされる。
