---
name: git
description: Git workflow helper. Handles staged commits with user approval and PR creation to develop branch.
argument-hint: commit | pr
---

$ARGUMENTSに応じて以下のいずれかを実行する。

---

## `commit` の場合

### Step 1: 変更内容を把握する

以下を実行して変更の全体像を把握する。

```
git status
```

```
git diff HEAD
```

### Step 2: コミット方針を立案する

取得した変更内容を論理的なまとまりでグループ化し、コミット分割案を作成する。

**グループ化の基準:**
- 機能単位（新機能、バグ修正、リファクタリング、設定変更など）
- 関連するファイル群をまとめる
- 1コミット1目的の原則を守る

作成した方針をユーザーに提示する。提示フォーマット：

```
## コミット方針

### コミット 1: <コミットメッセージ案>
- ファイル: <対象ファイル一覧>
- 内容: <変更内容の説明>

### コミット 2: <コミットメッセージ案>
...
```

### Step 3: ユーザーの承認を得る

AskUserQuestion ツールを使って確認する。

```
question: "上記のコミット方針で進めてよいですか？"
options:
  - label: "進める"
  - label: "修正が必要"
  - label: "キャンセル"
```

- 「進める」が選ばれたら Step 4 に進む
- 「修正が必要」の場合は方針を修正して再提示する
- 「キャンセル」の場合はここで終了する

### Step 4: コミットを実行する

承認された方針に従い、グループごとに順番にコミットを実行する。

各コミットで行う操作:
1. 対象ファイルを `git add <files>` でステージング（`git add .` は使わない）
2. `git commit -m "<メッセージ>"` でコミット

コミットメッセージのフォーマット:
- 1行目: 変更内容の要約（日本語可、50文字以内）
- 必要に応じて空行+詳細を追加

### Step 5: push コマンドを案内する

すべてのコミット完了後、以下のメッセージを表示する：

```
✅ コミット完了。push するには以下を実行してください：
```

そして push コマンドをユーザーがコンソールで実行できる `!` 付きの形式で提示する：

```
! git push
```

リモートブランチが未設定の場合は代わりに以下を提示する：

```
! git push -u origin <現在のブランチ名>
```

---

## `pr` の場合

### Step 1: 現在の状態を把握する

```
git fetch origin
```

```
git status
```

```
git branch --show-current
```

```
git log origin/develop..HEAD --oneline
```

### Step 2: PRの内容をまとめる

develop ブランチとの差分をもとに PR のタイトルと説明文を作成する。

- タイトル: 変更内容を端的に表す（50文字以内）
- 説明: 変更の目的・内容・テスト方法を含める

### Step 3: ユーザーの承認を得る

AskUserQuestion ツールを使って確認する。

```
question: "上記の内容で PR を作成してよいですか？"
options:
  - label: "作成する"
  - label: "修正が必要"
  - label: "キャンセル"
```

- 「作成する」が選ばれたら Step 4 に進む
- 「修正が必要」の場合は内容を修正して再提示する
- 「キャンセル」の場合はここで終了する

### Step 4: PR を作成する

`gh` CLI を使って develop ブランチへの PR を作成する。

```
gh pr create --base develop --title "<タイトル>" --body "<説明>"
```

PR が作成されたら、URL をユーザーに表示する。

`gh` が使えない場合は、ユーザーが手動で PR を作成できるよう、タイトルと説明文をそのまま表示して終了する。
