# Secretary システム 要件定義書

PC に常駐し、ユーザーの作業内容を観測して、指示がなくても自動で先回りの調査・検討を行う「秘書」アプリの要件定義。

関連ドキュメント: [architecture.md](architecture.md)（アーキテクチャ設計書）

---

## 1. 背景・目的

- ユーザーが今取り組んでいること（コード・チケット・予定）に対して、**指示を待たずに**参考になる調査・レビュー・下書きを準備してくれる存在がほしい
- LLM に自由な自律実行をさせる以上、**安全性（隔離環境での実行）を最優先**とする
- 既存資産（long-memory / mattermost-gate / Claude Code フック）を最大限流用する

### コンセプト

秘書の動作は次のループに分解される：

```
観測（何をしているか収集）
  → 文脈理解（今の関心事・詰まっている点を推定）
  → タスク生成（先回りできる調査・検討を起案）
  → 隔離実行（使い捨て環境の Claude Code が実行）
  → 報告（結果を通知、価値がなければ何もしない）
```

基本方針: **常駐するのは軽量な観測係のみ。LLM を動かす部分は毎回使い捨て。**

## 2. ユースケース

| # | ユースケース | 例 |
|---|---|---|
| UC1 | 閲覧中チケットの先回り調査 | JIRA チケット `PROJ-1234` を10分以上閲覧している → チケット内容と関連コードを調査し、対応方針メモを下書き |
| UC2 | 作業の詰まり検知 | Claude Code セッションログで同じエラーに繰り返し遭遇している → 別アプローチの調査資料を作成 |
| UC3 | 予定起点の資料準備 | Outlook カレンダーに明日レビュー会議がある → 対象ブランチの diff サマリと論点リストを準備 |
| UC4 | 変更のレビュー | 新しいコミットが積まれている → セルフレビュー観点でのコメント案を作成 |
| UC5 | 記憶を踏まえた提案 | long-memory の過去の意思決定と矛盾する変更を検知 → 過去の経緯を添えて注意喚起 |

いずれも成果物は「ユーザーが使える参考資料」であり、**ホスト環境への直接変更は行わない**。採用するかどうかは常に人間が判断する。

## 3. 機能要件

### 3.1 情報収集（Collector）

| ソース | 取得方法 | 備考 |
|---|---|---|
| Claude Code セッションログ | `~/.claude/projects/*.jsonl` | 最も濃い作業文脈 |
| git アクティビティ | 対象リポジトリの log / diff / branch | |
| アクティブウィンドウ | Win32 API（`GetForegroundWindow`）で プロセス名 + ウィンドウタイトルを10秒間隔でポーリング | 全アプリ対象（ブラウザ / VSCode / Mattermost / Word 等）。滞在時間で関心度を重み付け |
| ブラウザ履歴（補助） | Chrome / Edge の History（SQLite）を定期コピーして読み取り | タイトルで不足する正確な URL の取得用。デバッグポートは開放しない |
| JIRA | ウィンドウタイトル等から抽出したチケットキー → REST API（読み取り専用トークン）で詳細・差分取得 | スクレイピングはしない |
| Outlook カレンダー | Playwright（ヘッドレス + 永続プロファイル） | ID/PW 認証。詳細は architecture.md |
| Mattermost | 閲覧中チャンネル名（ウィンドウタイトル）+ API でのチャンネル読み取り | |

**収集の原則（プライバシー）:**

- アクティブウィンドウは**プロセス名／タイトルパターンの許可リスト方式**。マッチしないウィンドウは記録すらしない
- ブラウザ履歴も**ドメイン許可リスト方式**（JIRA・Confluence 等の明示したドメインのみ）
- VSCode は `window.title` 設定に `${activeEditorLong}` を含めることでフルパス取得の精度を上げる（導入時に設定）

### 3.2 トリガー

- **30分ごとの定期起動**（Windows Task Scheduler）
- 将来的にイベント駆動（SessionEnd フック・git commit 検知）の併用を検討するが、初期スコープ外

### 3.3 タスク起案・実行

- Orchestrator は LLM 判断を持たず、**Worker を毎回強制起動**する
- 起案（何をやるか／何もしないか）の判断は **Worker 自身**が行う
- コスト抑制のため、スナップショット先頭の差分サマリだけで続行/終了を判断する**早期終了パス**を Worker のプロンプトに明示する（変化がない回は1〜2ターンで終了）

### 3.4 先回りの範囲

- 許可: コードレビューコメント案 / 調査メモ / ドキュメント・返信の下書き / 論点整理 など**参考資料の生成**
- 禁止: ホストファイルの直接変更 / メール送信・チケット更新など外部への書き込み / 資料生成を超える自動アクション

### 3.5 出力

| 経路 | 内容 |
|---|---|
| Mattermost 投稿 | 成果サマリ + 生成ファイルへのパス。**成果があった回のみ投稿**（何もしなかった回は無音）。日次ダイジェストは将来検討 |
| 共有ディレクトリ | `C:\claude\secretary-workspace\`（仮）配下に成果物を書き込み。Worker が rw マウントできる**唯一の**ホスト領域 |

### 3.6 長期記憶（long-memory 連携）

- Worker が **secretary-gateway（MCP）経由で読み取り専用検索**を行う（`memory_search` ツール）
- 検索タイミング・クエリは Worker の自由判断
- **Worker は記憶を書かない**。記憶の蓄積は既存のフック駆動保存（ユーザー自身のセッション）に任せる

## 4. 非機能要件（安全性最優先）

| 要件 | 内容 |
|---|---|
| ネットワーク egress 制限 | Worker から出られる先は **Anthropic API + secretary-gateway の2経路のみ** |
| 認証情報の分離 | Worker に渡る秘密情報は**支出上限つき Anthropic API キー1つだけ**。JIRA / Outlook / Neo4j / Mattermost の認証情報は Worker に渡さない |
| 書き込み境界 | Worker の書き込み先は共有ディレクトリのみ。ホストの他領域はマウントしない |
| 使い捨て実行 | Worker はジョブごとに新規コンテナ・終了後破棄。状態の持ち越しなし（ステートレス） |
| コスト・時間上限 | 1ジョブあたりの `max_turns` / timeout、日次起動回数上限 |
| 監査ログ | 起動ジョブ・渡したスナップショット・出力・採否を JSONL で全件記録（mattermost-gate の `audit.py` パターンを踏襲） |
| プロンプトインジェクション耐性 | 収集した Web / JIRA / Mattermost コンテンツは信頼しない前提で、被害範囲を境界設計で限定（詳細は architecture.md「安全性設計」） |

## 5. 制約事項

| 制約 | 影響と対応 |
|---|---|
| Neo4j は Community Edition（RBAC 不可） | 読み取り専用ユーザーが作れない → Worker に Bolt 直接続させず、**secretary-gateway（MCP）で読み取り専用ツールとして提供** |
| Outlook は Playwright のみ（Graph API 不可） | ID/PW での自動ログイン + 永続プロファイル。認証情報は gateway コンテナに隔離 |
| Ollama は Windows ネイティブ稼働 | 記憶検索の Embedding 生成は gateway 内に閉じ、Worker からは見えない |
| Docker は WSL2（Ubuntu-24.04） | Worker / gateway は WSL2 上の Docker で稼働。Pod/k8s は現時点で不要 |
| PowerShell パイプの BOM 問題 | JSON 受け渡しはファイル経由を基本とする（CLAUDE.md 記載の既知問題） |

## 6. 段階的導入（MVP）

| Phase | 収集ソース | 追加コンポーネント | ゴール |
|---|---|---|---|
| **Phase 1** | セッションログ + git + アクティブウィンドウ | Collector / Orchestrator / Worker（gateway なし） | 30分サイクルで1周し、Mattermost に成果が届く |
| **Phase 2** | + JIRA + long-memory 検索 | secretary-gateway（`memory_search` / `jira_*`） | 閲覧中チケットの先回り調査（UC1）が動く |
| **Phase 3** | + Outlook + Mattermost 読み取り | gateway に `calendar_get_events` / `mattermost_read` 追加 | 予定起点の資料準備（UC3）が動く |

## 7. 用語

| 用語 | 意味 |
|---|---|
| Collector | Windows 常駐の軽量観測プロセス。イベント JSONL に追記するだけ |
| Orchestrator | 30分ごとに起動する決定的スクリプト群（LLM なし）。スナップショット生成 → Worker 起動 → 回収 → 投稿 |
| Worker | 使い捨てコンテナ内の Claude Code（Agent SDK）。唯一 LLM の自由判断を持つ |
| secretary-gateway | WSL2 Docker 常駐の MCP サーバー。外部サービスへの読み取り専用ツールと認証情報を集約 |
| スナップショット | Orchestrator が生成し Worker に読み取り専用で渡す入力パッケージ |
| 共有ディレクトリ | Worker が書き込める唯一のホスト領域。成果物の受け渡し場所 |
