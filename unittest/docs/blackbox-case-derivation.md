# ブラックボックステストケース生成スキル 設計書

外部設計書（Excel）から機械的に情報を抽出し、テストケースを体系的かつ漏れなく
生成するスキルの設計書。インプット・処理フロー・アウトプットを定義する。

---

## 1. スキル概要

### 目的

実システムでは画面数・項目数が多く、Claude Code が設計書を読んでテストケースを自由生成すると以下の省略が発生しやすい。

| 省略パターン | 具体例 |
|---|---|
| ハッピーパス偏重 | 正常入力のケースのみ作成し、未入力・桁超過を漏らす |
| 境界値の片側欠落 | 最大値ちょうどはテストするが、最大値+1 を漏らす |
| チェック条件の組み合わせ漏れ | 複数条件の AND/OR 組み合わせで一部パスを漏らす |
| 異常クラスの網羅不足 | 数値項目に文字列を入力するケースを漏らす |

### 解決アプローチ

「テストケースを生成する」という創造的タスクを、「インベントリ行をカバーする」という機械的タスクに分解する。

```
Step A  外部設計書（Excel）を解析 → インベントリ（I-ID / C-ID 付き一覧）を作成
Step B  インベントリ → テストケースを対応付け（Claude Code に指示）
Step C  インベントリの全行に TC-ID が割り当てられているかを確認表でチェック
```

インベントリが「チェックリスト」として機能するため、省略が検知可能になる。

### 適用対象

| 設計書種別 | インベントリ種別 | テスト技法 |
|---|---|---|
| 画面項目定義シート | 項目定義インベントリ（I-ID） | 同値分割・境界値分析 |
| チェック仕様シート | チェック仕様インベントリ（C-ID） | デシジョンテーブル |

## 2. インプット

スキル実行に必要な情報を以下に定義する。`excel-extractor` CLI のオプションと対応している。

| 項目 | CLI オプション | 必須 | 説明 |
|---|---|---|---|
| 解析対象 Excel ファイル | 位置引数 `<excel_file>` | ✓ | `.xlsx` 形式のみ対応 |
| ボタン名 / イベント処理名 | `--button` / `-b` | ✓（常に必須） | チェック仕様をボタン単位で絞り込む。空欄＝全ボタン共通のチェックは常に含まれる |
| config.yaml パス | `--config` / `-c` | 任意 | 省略時: `excel-extractor/config.yaml`。設計書フォーマットが異なる場合に指定 |
| 出力先 Markdown | `--output` / `-o` | 任意 | 省略時は標準出力 |

### 制約

- `--button` は常に必須（省略不可）
- 解析対象ファイルは `.xlsx` のみ対応（`.xls` は非対応）

## 3. 処理フロー

### Step A — excel-extractor CLI でインベントリを生成

#### セットアップ（初回のみ）

```toml
# pyproject.toml の dependencies に追記
"openpyxl>=3.1",
"pyyaml>=6.0",
```

```powershell
uv sync
```

#### CLI コマンド例

```powershell
# 登録ボタンのインベントリを標準出力に表示
uv run python unittest/excel-extractor/excel_extract.py design.xlsx --button 登録

# 登録ボタンのインベントリを Markdown ファイルに出力
uv run python unittest/excel-extractor/excel_extract.py design.xlsx --button 登録 `
  --output unittest/docs/inventory-register.md

# 更新ボタンのインベントリを別ファイルに出力
uv run python unittest/excel-extractor/excel_extract.py design.xlsx --button 更新 `
  --output unittest/docs/inventory-update.md

# 設計書フォーマットが異なる場合（別 config を使用）
uv run python unittest/excel-extractor/excel_extract.py design.xlsx --button 登録 `
  --config unittest/excel-extractor/config-format2.yaml `
  --output unittest/docs/inventory-register.md
```

#### Step A の出力形式

Step A の成果物は「インベントリ Markdown」（項目定義 + チェック仕様）。詳細は[セクション 4](#4-アウトプット形式) を参照。  
I-ID / C-ID 採番規則の詳細は `blackbox-excel-extractor-policy.md` セクション 6 を参照。

#### Step A 完了後の確認事項

- [ ] 全画面・全項目が I-ID として登録されているか
- [ ] 必須/任意が正しく取り込まれているか
- [ ] 最小値・最大値が数値として正しく抽出されているか（Excelのセル書式の影響に注意）
- [ ] チェック仕様の全チェックIDが C-ID として登録されているか
- [ ] セル結合によって読み飛ばしが発生していないか（ツールの警告を確認）

---

### Step B — インベントリから Claude Code でテストケースを導出

#### 対応付けルール

```
項目定義インベントリの「1行（= 1項目）」に対して、
  → 同値分割クラス数 + 境界点数 のテストケースを生成する

チェック仕様インベントリの「1行（= 1チェック条件）」に対して、
  → 条件が成立するケース と 成立しないケース を最低1つずつ生成する
```

1つのテストケースが複数のインベントリ行をカバーする場合は共有可能。  
ただし、正常/異常が逆のケースを同一テストケースで担うことは不可。

テスト技法別の具体的な導出ルールは[付録](#付録-テスト技法別テストケース導出ルール)を参照。

#### Claude Code への指示プロンプトテンプレート

```
以下のインベントリに基づき、テストケース一覧を作成してください。

【インベントリ: 項目定義】
<ここに項目定義インベントリの Markdown テーブルを貼り付ける>

【インベントリ: チェック仕様】
<ここにチェック仕様インベントリの Markdown テーブルを貼り付ける>

【制約】
- 各 I-ID に対して「同値分割クラス数 + 境界値 on/off 点」の分テストケースを生成すること
- 各 C-ID に対して「条件成立ケース」と「条件不成立ケース」を最低1つずつ生成すること
- テストケース作成後、最後に「カバレッジ確認表」を出力すること

【カバレッジ確認表の形式】
| I-ID / C-ID | テスト観点             | 担当 TC-ID   | カバー済み |
|-------------|----------------------|-------------|----------|
| I-a1b2c3    | 正常クラス代表値        | TC-BB-03    | ✓        |
| I-a1b2c3    | 下限 on（最小値）      | TC-BB-03    | ✓        |
| I-a1b2c3    | 下限 off（最小値-1）   | TC-BB-02    | ✓        |
| I-a1b2c3    | 上限 on（最大値）      | TC-BB-04    | ✓        |
| I-a1b2c3    | 上限 off（最大値+1）   | TC-BB-05    | ✓        |
| I-a1b2c3    | 未入力（必須項目の場合）| TC-BB-01    | ✓        |
| I-a1b2c3    | 型異常（非数値）        | TC-BB-06    | ✓        |
| C-j1k2l3    | 条件成立              | TC-BB-09    | ✓        |
| C-j1k2l3    | 条件不成立            | TC-BB-10    | ✓        |
...

- カバレッジ確認表に「未割当」行が 0 件であることを確認してから終了すること
```

---

### Step C — カバレッジ確認表でチェック

Step B で出力されたカバレッジ確認表を確認し、全インベントリ行に TC-ID が割り当てられていることを検証する。

```
□ カバレッジ確認表の「未割当」行が 0 件か
□ インベントリの全行に TC-ID が割り当てられているか
```

## 6. カバレッジ確認チェックリスト

テストケース作成完了後（Step B 後）、以下を確認する。

### 項目定義インベントリ（I-ID）別チェック

```
□ 必須項目    未入力ケース がある か
□ 数値項目    下限 on / off / 上限 on / off の 4 点がある か
              （+ 正常クラス代表値 を合わせた 5 点が基本）
□ 文字列項目  最小長 on / off（= 空文字）/ 最大長 on / off の 4 点がある か
□ 型制約      期待型と異なる値（非数値・記号・全角など）のケースがある か
□ 許容値リスト 各許容値 + 非許容値 のケースがある か
```

### チェック仕様インベントリ（C-ID）別チェック

```
□ 各 C-ID に「条件成立」ケースが最低 1 つある か
□ 各 C-ID に「条件不成立」ケースが最低 1 つある か
□ 複数条件が AND 結合の場合、「全条件成立」「1条件のみ不成立」の各ケースがある か
□ 複数条件が OR 結合の場合、「全条件不成立」「1条件のみ成立」の各ケースがある か
```

### カバレッジ確認表チェック（Step C）

```
□ カバレッジ確認表の「未割当」行が 0 件か
□ インベントリの全行に TC-ID が割り当てられているか
```

### 設計品質チェック

```
□ 1つのテストケースに正常・異常の両方が混在していないか
□ 期待結果に具体的なエラーメッセージが記載されているか（チェック仕様インベントリの内容と一致するか）
□ 境界の in 点は正常クラス代表値と兼用してよいが、on 点は必ず独立させているか
```

## 付録: テスト技法別テストケース導出ルール

### A.1 同値分割

入力ドメインを「正常クラス」「異常クラス」に分け、各クラスの代表値 1 つでテストする。

```
入力例: 在庫数（整数、0〜9999）

正常クラス: 0 ≤ 値 ≤ 9999 → 代表値: 1（または適切な中間値）
異常クラス①: 値 < 0        → 代表値: -1
異常クラス②: 値 > 9999     → 代表値: 10000
異常クラス③: 非数値         → 代表値: "abc"
```

| アウトカム | テストケースで用意するもの |
|---|---|
| 正常クラス | 範囲内の代表値 1 つ |
| 異常クラス（境界超過） | 範囲外の代表値 1 つ |
| 異常クラス（型違い） | 期待型と異なる値 1 つ |
| 必須チェック | 未入力（空文字・null） |

### A.2 境界値分析

数値・文字列長の境界は 4 点モデルで検討する。

```
on 点 : 境界値ちょうど（最小値・最大値）
off 点: 境界の外側 1 つ（最小値-1・最大値+1）
in 点 : 境界の内側 1 つ（最小値+1・最大値-1）
※ in 点は同値分割の正常クラス代表値と兼用可能
```

| 境界点 | 名称 | 在庫数（0〜9999）の例 |
|---|---|---|
| 最小値 on | 下限ちょうど | 0 |
| 最小値 off | 下限の1つ外 | -1 |
| 最小値 in | 下限の1つ内 | 1 |
| 最大値 in | 上限の1つ内 | 9998 |
| 最大値 on | 上限ちょうど | 9999 |
| 最大値 off | 上限の1つ外 | 10000 |

> 最小値と最大値が等しい（= 固定値）の場合は on 点 1 つ + off 点 2 つ = 3 ケース。

文字列長の例:

| 境界点 | 名称 | 商品名（最大50文字）の例 |
|---|---|---|
| 0 文字 | 空文字（未入力） | "" |
| 1 文字 | 下限 in | "A" |
| 49 文字 | 上限 in | "A" × 49 |
| 50 文字 | 上限 on | "A" × 50 |

### A.3 デシジョンテーブル

チェック仕様の条件と処理結果を表で整理する。  
チェック仕様は入力バリデーションではなく業務ロジックの条件（「XXがYYのとき ZZZ を表示」）を表す。  
1行 = 1条件 + 条件成立時のエラーメッセージ。条件不成立時は別行として記載される。

```
チェック例（注文処理）:
  CHK-001: 在庫数 < 注文数     → エラー「在庫が不足しています」
  CHK-002: 注文金額 > 与信限度額 → エラー「与信限度額を超えています」
```

| 条件/アクション | TC-BB-01 | TC-BB-02 | TC-BB-03 | TC-BB-04 |
|---|---|---|---|---|
| 在庫数 < 注文数: 成立     | ✓ | - | - | - |
| 在庫数 < 注文数: 不成立   | - | ✓ | ✓ | ✓ |
| 注文金額 > 与信限度額: 成立 | - | - | ✓ | - |
| 注文金額 > 与信限度額: 不成立| ✓ | ✓ | - | ✓ |
| → エラー CHK-001 | ✓ | - | - | - |
| → エラー CHK-002 | - | - | ✓ | - |
| → 正常処理続行   | - | ✓ | - | ✓ |

複数条件が同時成立しうる場合は全組み合わせを列挙する。  
排他的な場合は各条件を独立ケースとして扱う。
